# MathPath Project 评估与真实试用

本项目按 NLP 课程的 Project 路线准备。软件检查、模型内容评审和真实学习效果分别报告；任何空白评分或模拟数据都不作为已完成的真实用户测试。

## 三层评估

1. 软件可靠性：运行离线回归、前端交互和真实桌面窗口检查。重点覆盖 AND/OR 推荐、来源限制、存储冲突、历史恢复、批量移动与删除、删项目保留历史，以及模型候选反馈不能自动成为独立通过记录。浮动提问窗口还检查拖动与缩放边界、连续问答、问答恢复、取消与切换记录时的迟到回复隔离。完整备份另检查预览不添加、确认后原子追加、项目与问题关联保持、默认重复保护及明确再次添加；软件测试与真人恢复观察分别报告。
2. NLP 与数学内容质量：沿用本目录的 20 个目标、40 个模拟状态，显式采集实际模型输出后按 `README.md` 的六个维度人工评分。记录每次失败与实质数学错误，并计算结构有效率、请求成功率、各维度得分分布和错误率。不能把离线结构检查称为模型生成实验。
3. 真实用户：至少邀请 3 名实际使用者，填写 `user-feedback-template.csv`，留下改进依据。先观察使用困难；要检验实际学习，再安排独立前测、后测和延迟测验。

## 试用任务

每名用户选择适合其背景的一个数学目标，按以下顺序试用。可从无需登录的三套完整样例中任选：同调取商、有限维实线性映射的秩—零度定理、简单仿射函数的 ε–δ 极限证明。记录所选主题与先备知识，避免把主题难度差异误算为软件差异；之后再按需用其自己的模型配置测试新目标生成。固定样例是经过开发者审阅的演示内容，不计为真实模型生成成功。

- 用自己的话描述困惑，并完成或跳过短诊断。
- 试一次宽泛目标，检查是否先出现相关方向，选一个具体目标再确认生成；记录漏检或误检。
- 打开学习卡，查看先修解释，完成一次微练习和一次开放作答；按需使用提示。
- 打开“随时提问”，移动窗口避免遮住正在看的内容；针对一个知识点连续提出两个问题，第二问引用第一问中的符号或步骤。区分本地已有参考与模型新回答。
- 将仍未理解的问题存入“未解决问题”，检查原问题与目标是否保留；实际解决后手动标记。只用演示记录测试重新打开和所选删除。
- 选择证明层级或自报三个能力均掌握，查看参考书的相关性、章节和官方来源；未知主题没有推荐时也如实记录。
- 记录一条笔记，关闭后重新打开这条学习历史，检查是否恢复。
- 创建一个项目，把历史移进去。用额外的演示记录测试多选删除；删除演示项目后检查历史转入未分类。保留自己的重要学习记录。
- 用演示项目和演示历史测试完整备份：先添加一条笔记、一次作答、一轮本地参考问答及一个未解决问题，再在“历史 / 项目”点击“完整备份学习库”。记录导出前的项目、历史和问题数量，以及演示记录之间的关联。备份覆盖本机全部学习库，不只导出演示项目，因此应使用专门的演示数据目录，不把含私人内容的文件交给他人或公开。
- 点击“恢复完整备份”选中刚导出的 JSON，查看数量后先取消预览，确认没有新增记录。再选同一文件，确认追加恢复；检查原有内容保留、备份中的记录作为新记录添加，项目归属、卡片、笔记、作答、问答与未解决问题的内容、解决状态和关联均保持。ID重新分配属正常行为，按内容与关联检查，不要求原 ID 相同。
- 再选已恢复的备份，核对“已经恢复过”的提示。只有明确确认再次添加才应产生另一份记录；取消不产生重复。只用演示记录检验这个行为，记录新增数量；不要在真实学习库中反复添加整份备份。
- 完成一项最终独立检验，说明哪处帮助有效、哪处仍不清楚，并记录至少一条具体意见。

试用者自己决定是否连接模型或使用额度。反馈表使用匿名编号，不收集账号、API 密钥、订阅链接或无需收集的身份信息。

## 量化指标与报告方式

| 类别 | 指标 | 记录方法 |
| --- | --- | --- |
| 任务完成 | 完成任务数 / 尝试任务数 | 保留未完成任务和原因 |
| 交互效率 | 完成各任务的时间、求助次数 | 人工观察或用户自行记录；区分网络等待 |
| 内容质量 | 6 项人工评分与实质错误数量 | 指明对应节点、题目或步骤的证据 |
| 连续问答 | 问题相关性、前文衔接、数学约定一致性与错误数 | 对保存的问答人工评审，标出引用的具体条件或步骤；离线转发测试不代表回答质量 |
| 目标细分 | 宽泛输入检出率、具体输入误检率、方向相关性 | 预先标注真实输入，再统计；本地规则显示选项不等于理解了所有数学目标 |
| 问题与书目 | 未解决问题保留率、误记录率、教材相关性 | 对实际问答人工复核；模型的回答状态及自报掌握不能代替正确性判断 |
| 备份导出 | 成功导出次数 / 明确尝试导出次数 | 记录无效格式、大小上限、保存冲突或存储失败；不删除失败尝试 |
| 备份恢复 | 内容和关联完整的追加恢复次数 / 明确确认追加且实际发出请求的次数 | 首次恢复与用户明确再次添加分别记录；取消预览、只看提示和未发出请求不计入此分母。核对预计新增与实际新增数量，并保留失败及原因；尚未人工检查的成功响应标为待核，不直接计成功 |
| 恢复交互 | 取消后无新增次数 / 取消预览次数；重复提示出现次数 / 选中已恢复备份次数 | 使用演示记录；默认重复保护与明确再次添加分开，不把取消当恢复失败 |
| 理解检验 | 无提示答题表现、提示依赖 | 使用与原始目标对应的评分要点 |
| 用户体验 | 易用性与有用性各 1–5 分 | 同时收集具体原因，不仅平均分 |
| 优化效果 | 修改前后的同类任务表现 | 保留版本、修复内容与复测结果 |

如果做对照实验，MathPath 与普通 LLM 问答应使用同一模型、相近难度的主题和相同学习时间。控制先备知识，交叉安排时注意顺序和迁移影响；后测使用未见过的同等难度变式。隔几天的延迟测验需要真实进行后再填分数。3 人试用足以发现一些可用性问题，不能支持普遍或显著提高学习效果的结论。

## 已实现的同模型教学决策对照

[compare.py](compare.py) 提供可执行的采集入口，[review.py](review.py) 负责匿名人工评审与评分校验，固定设计和结果解释见 [experiment-plan.md](experiment-plan.md)；完整命令见 [评测说明](README.md)。离线准备得到20个目标、40个模拟自报状态和80行空评分计划，没有真实分数。

在相同模型配置、共用指令与输出格式下，A收到目标、困惑和完整自报状态，B在相同内容上增加人工审核的AND/OR图及人工已知节点映射。先核实图和映射并填写批准证据，再显式采集；工具不会自动推断已知节点或让模型给自己评分。每状态/试次随机交错请求条件；失败、尚未请求和未评输出分别保留。一个目标的两个状态、两个条件、每条件3次是12次真实请求，会使用当前账号额度或API费用。

采集后隐藏条件与模型标识、打乱输出编号，交给审阅者填写0–2分、实质错误和具体证据；揭盲文件由协调者另行保管。输出措辞仍可能泄露条件，因此只称匿名评审。汇总报告有效分数分母、未评数、失败率、得分分布与同一审阅者的完整A/B配对差；空分数保持缺失，不填0，不以成功样本替换全部请求分母。

该对照只能描述**人工审核结构上下文对下一步教学决策输出质量的影响**。它不检验自动构图的端到端可靠性，也不测量用户掌握、成绩或长期学习提升。真实学习效果须用独立题目、真实参与者和适当对照另行测试；本轮工具准备不表示已完成真实pilot或真人评审。

若单独评估对话上下文，可预先编写一组“问题—追问”，在同一模型配置下比较包含学习图、所选学习卡及前文的回答，与只提供当前问题的回答。固定采样条件，隐去版本标识后人工评分，分别报告上下文有帮助、无影响或引入错误的案例；不能预设带上下文一定更好。

## 现场 Demo 建议

展示“目标 → 学习图 → 本地规划 → 学生作答 → 反馈与下一步建议 → 连续提问 → 保存历史 → 项目归类 → 再次恢复”的完整过程。三套离线样例按演示对象选择一套，提前核对共同数学约定；可用演示库追加展示“完整备份 → 预览取消 → 确认追加恢复 → 检查历史与问题关联”。模型生成是否实时成功如实说明，提前保存的内容明确标为已存内容；完整备份不包含账号或模型设置，换电脑需要单独配置。

GitHub 仓库应包含源代码、README、运行方式、评测方法和第三方许可。公开内容先排除 `.mathpath`、实际数据库、API 密钥、授权记录和含私人学习内容的原始试用资料。当前文档只是准备材料，不能代替真实仓库链接或 3 名真实用户的反馈。
