# XGI 与 MathPath 先修组：表示、边界与本轮改进

核查日期：2026-10-28。参考 [xgi-org/xgi](https://github.com/xgi-org/xgi)，按正式版 [v0.10.2](https://github.com/xgi-org/xgi/releases/tag/v0.10.2) 的固定提交 [`a61d670`](https://github.com/xgi-org/xgi/tree/a61d6700096c3b5e864f34ef58c415f7b5c072ff) 阅读有向超图、二部图转换、绘图和依赖说明。未安装或执行 XGI；以下是源码研究和 MathPath 自写实现，不是 XGI 的运行性能评测。

## 为什么适合借鉴

XGI 是高阶网络工具库，与 DeepTutor 的教学系统定位不同。它对 MathPath 最有帮助的是保留“一组知识共同构成先修”的表示，而不是替系统选择数学教学内容。

例如 `T.prerequisite_sets = [[A, B], [C]]` 对应两条有向超边：

```text
tail = {A, B}, head = {T}    第一条完整路线
tail = {C},    head = {T}    第二条完整路线
```

每条边内需要全部满足，多条边之间任选一条。这是 **MathPath 赋予超边的教学规则**；XGI 存储 tail/head，不会自动理解“掌握”“全部满足”或“最适合学习”。[DiHypergraph.add_edge](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/core/dihypergraph.py#L525-L582)

当前 MathPath 的 `prerequisite_sets` 已经保留这个结构，不需要为使用新库而改写旧学习历史。规划仍以本图最多 12 个节点为界，精确比较需学节点数；共享先修只计一次，已自报够用的高级节点是展开边界，不反推其祖先已掌握。

## 二部表示能帮助解释，不能代替激活判定

XGI 的有向二部转换采用 `先修节点 → 超边节点 → 后续节点`。MathPath 已有的 SVG “全部 / 任选一组”门可以继续采用这一表示。[转换实现](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/convert/bipartite_graph.py#L156-L199)

但存在 `A → 组 → T` 的普通路径，并不说明同组的 B 也满足。当前可学的判定必须始终检查 `any(all(member in planning_known for member in group) for group in groups)`；不能直接换成普通图最短路或可达性。[上游 shortest_path](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/algorithms/shortest_path.py#L10-L64)

转换还会重编号节点；需要 `index=True` 才得到反向映射，业务标签和属性也需要另行保留。MathPath 以当前图内的 `(node_id, group_index)` 定位一组，并保留原组和成员顺序。这个索引只标识当前图，不应当作跨路线修订仍不变的版本 ID。

## 本轮落地范围

`/plan` 新增两类解释数据，兼容既有响应字段与旧学习历史：

- `prerequisite_groups`：逐组返回原成员、当前目的下已够用的成员、仍缺成员、是否满足，以及是否被推荐路线选中。
- `unlock_previews`：对每个当前可学知识点，只假设它已达到当前目的所需能力，列出原本阻塞、现在刚满足先修的节点。

学习卡显示组内满足数量、缺少的知识点编号和所选路线。推荐候选和学习卡提供“补齐后新增可学”的只读预览。一个 AND 组还缺两项时，只补其中一项不会把后续误列为可学；预览也不会连锁假定新开放节点已经学会。

地图、先修摘要与路线统一使用 `planning_known_ids` 判断当前目的是否够用。全掌握进度继续使用三项自报全勾的 `known_ids`，二者不混用。切换模式会重新计算解释，不会把一次模式下的够用状态写成全部掌握。

这轮只改源码工作区的规划与展示；没有升级数据格式、调用真实模型、改变 API/登录设置或覆盖既有 Windows 发行包。已发布 v0.5.1 安装包不因此自动更新。

## 为什么保留轻量运行架构

正式版依赖包括 NumPy、SciPy、Pandas、Matplotlib 等；目前为了十余节点的解释和本地 SVG 展示，没有必要把整个分析绘图栈加入 Windows 软件。保留 NetworkX 排序与本地组判定，未来有超图统计、论文图或跨工具分析需求时，再增加可选 XGI 适配。[固定版本依赖](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/pyproject.toml#L5-L54)

未来适配可从已校验的 `KnowledgeGraph` 生成对象：先添加所有知识点，再用 `DH.add_edge((group, [node.id]), idx=group_id)` 添加每一组，保留目标 ID 和原顺序。基础节点没有已建模先修，因此只作为节点，不伪造空尾超边，也不视为已知。

有向绘图应使用 `draw_bipartite` 的有向分支；普通 `draw` 的类型分支不接受 `DiHypergraph`。当前本地 SVG 可继续承接交互，不需要将 Matplotlib 图片嵌入主流程。[draw 类型分支](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/drawing/draw.py#L299-L325) [有向二部绘图](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/drawing/draw.py#L1797-L1806)

## 不能直接采用的默认行为

1. `DiHypergraph` 仍标注实验性，并允许自环和重复边；`add_edge` 可自动添加未知成员。MathPath 仍须先严格检查节点引用、重复组、无环、目标和节点上限。[类型说明](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/core/dihypergraph.py#L20-L39) [自动补节点](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/core/dihypergraph.py#L567-L579)
2. 类说明中把无向成员写成 tail/head 交集，与实际 `members()` 的并集实现不一致。适配时显式使用 `tail/head/dimembers` 保留方向，不能复制这处文字作为数学定义。[真实 members 实现](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/xgi/core/views.py#L1093-L1122)
3. 度数、中心性、路径长度或一条边满足，不代表学习成效。预览仅解释当前图和自报状态，不能替代独立作答，也不改变模型候选反馈的 `review_required` 边界。
4. XGI 为 BSD-3-Clause；本轮采用表示思路并自写代码，没有复制上游实现或捆绑上游库。若后续复用源码，需保留适用的版权和许可声明。[许可](https://github.com/xgi-org/xgi/blob/a61d6700096c3b5e864f34ef58c415f7b5c072ff/LICENSE.md)

## 与 DeepTutor 方案如何衔接

DeepTutor 的下一教学动作可以使用这里的解释：推荐哪个节点、该先修组还缺什么、补齐后可以继续哪里。它不能用聊天措辞或模型置信度直接改写自报掌握。上一轮的聊天题卡、反馈质疑、来源和教学记忆方案见 [DeepTutor 对照研究](deeptutor-study-2026-10-27.md)，这些独立模块不冒充本轮已完成的功能。

验收分为组逻辑的独立真值检查、真实后端响应驱动的界面检查，以及临时学习库中的实际页面检查。它们验证软件行为，不证明模型数学正确性或学习效果；真实模型和真实用户评测继续分开记录。
